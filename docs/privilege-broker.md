# Privilege Broker v1

Бот работает от обычного пользователя. Когда режим `LSAB_BROKER=sudo`
включён, реестр выдаёт клиент брокера встроенному Docker и одобренным
внешним плагинам.
При вызове операции клиент проверяет декларацию плагина и отправляет
один JSON-запрос отдельно установленному helper через `sudo -n`.
Helper использует системный Python в изолированном режиме и завершается
после ответа.

## Граница доверия

- Системная граница проходит по защищённым файлам, правилу sudo и проверке
  UID вызывающего пользователя. Helper сверяет `SUDO_UID` и `SUDO_USER`
  с системной базой и политикой.
- ID плагина берётся из реестра. В общем процессе Python это логическая
  метка для доверенных блоков. Код с правами пользователя бота должен
  считаться способным вызвать любой выданный этому пользователю набор
  операций. Изоляция стороннего кода потребует отдельного процесса.
- Встроенные операции заданы в коде helper. Одобренные внешние операции
  добавляются в защищённую системную политику. Для каждого вызова helper
  проверяет разрешение, аргументы и ограничения. Окружение дочернего
  процесса задано в коде. Одобрение фиксированной команды требует проверки
  её фактического поведения от имени root, включая используемые конфиги.
  Ввод, вывод и время ограничены. Изменения Docker сериализуются блокировкой.
  Docker CLI использует отдельный пустой защищённый каталог конфигурации.
- Для изменений Docker администратор явно указывает полные неизменяемые ID
  контейнеров. Перед изменением helper сверяет фактический ID. Если список ID
  указан, он также ограничивает чтение. Доверие к daemon и другим операторам
  Docker остаётся частью модели хоста.
- Docker передаёт выбранные поля состояния и метрик.
  Переменные окружения контейнеров, аргументы запуска, ключи и внутренний
  вывод команд не выдаются клиенту и не пишутся в аудит.
- По умолчанию все рабочие операции запрещены. Некорректная политика,
  недоступность helper и тайм-аут возвращаются как структурированные ошибки.
  После тайм-аута проверьте результат на хосте перед повтором изменения.

## Подготовка и установка

`setup-native.sh` предлагает установить брокер из готового комплекта.
Можно также вызвать `./setup-native.sh --broker-bundle /root/lsab-broker-release`.
Комплект должен быть заранее проверен и размещён администратором в
защищённом каталоге. После успешной установки скрипт выставляет
`LSAB_BROKER=sudo` в `.env`.

Брокер опционален. Обычная установка бота сохраняет режим
`LSAB_BROKER=off`. Для нативного брокера используйте выделенного
пользователя бота без sudo к произвольным командам и без прямого доступа
к сокету или удалённому Docker API. При переходе удалите прямые
разрешения Docker, например членство
в группе `docker`. Установщик отклоняет группу `docker` и доступную
на запись стандартную точку сокета.

Соберите архив от непривилегированного пользователя из проверенного исходного
дерева. Архив содержит только пакет `broker` и запускной модуль.

```bash
python3 packaging/broker/build.py /tmp/lsab-broker-release
```

Администратор размещает проверенную копию `install.sh` и `lsab-broker`
в своём защищённом каталоге, например `/root/lsab-broker-release`, и
запускает **эту копию** от root. Проверьте содержимое поставки до запуска:
установщик и архив являются привилегированным кодом. Обычная рабочая копия
бота и его виртуальное окружение для установки от root не используются.

```bash
/root/lsab-broker-release/install.sh serverbot
```

Установщик размещает защищённые копии в
`/usr/local/libexec/lsab-broker/lsab-broker` и
`/usr/local/sbin/lsab-broker-admin`. Для первого запуска он создаёт
`/etc/lsab/broker/permissions.toml` с разрешённым UID и пустым каталогом
выданных действий. При обновлении существующая политика сохраняется.
Правило `/etc/sudoers.d/lsab-broker` проходит проверку `visudo` и разрешает
учётной записи запускать только helper без аргументов. Административная
команда находится по отдельному пути и требует отдельного доступа root.

Пример выдачи и отзыва разрешений от системного администратора.

```bash
sudo /usr/local/sbin/lsab-broker-admin grant docker docker.containers.read
sudo /usr/local/sbin/lsab-broker-admin grant docker docker.containers.inspect
sudo /usr/local/sbin/lsab-broker-admin revoke docker docker.containers.inspect
```

Для `docker.containers.start`, `stop` или `restart` при первом таком
гранте добавьте `--container FULL_CONTAINER_ID`. Используйте 64 строчных
шестнадцатеричных символа без префикса. Для экрана деталей отдельно
предоставляются `docker.containers.inspect` и `docker.containers.stats`.
Для смены списка ID администратор может изменить защищённый TOML и проверить
его командой `lsab-broker-admin check-policy`.

Укажите `LSAB_BROKER=sudo` в `.env` нативной установки, включите нужные
блоки и запустите проверку перед перезапуском бота.

```bash
lsab broker status
lsab broker doctor
lsab broker actions
lsab broker info docker.containers.restart
lsab permissions list
lsab permissions requested docker
lsab permissions missing docker
lsab permissions browse
lsab plugins check
```

`permissions requested` читает декларации офлайн. `granted`, `missing`
и интерактивный просмотр обращаются к нативному helper от имени текущего
пользователя. `broker doctor` выявляет отсутствующие системные программы,
а `plugins doctor` проверяет доступность конкретного блока с его настройками.

Аудит можно смотреть через `journalctl -t lsab-broker`. Записи содержат UID,
системное имя, заявленный ID плагина, известное действие, код и длительность.
Параметры и вывод операции в аудит не включаются.

При обновлении с версии со встроенным CrowdSec установите новый helper.
Он принимает старые файлы политик с известными разрешениями CrowdSec,
исключая эти разрешения из активной политики.

## Docker Compose

Контейнерная установка бота продолжает обслуживать непривилегированные
блоки. Compose не монтирует сокет Docker и не добавляет группу доступа
к нему. При обновлении пересоздайте прежний контейнер, чтобы убрать старый
mount и группу доступа. Для управления Docker на хосте используйте нативную
установку бота с брокером. Отдельный транспорт между контейнером и
брокером хоста относится к следующему развитию архитектуры.
