# Установщик внешних плагинов

`lsab plugins` управляет пакетами в нативном виртуальном окружении бота.
Установка выполняется от имени пользователя бота. Новые блоки появляются
в реестре выключенными. Включение через `lsab plugins enable` и предоставление
системных разрешений брокера остаются отдельными действиями.

## Источники и предварительный просмотр

```bash
lsab plugins install /path/to/plugin.whl --dry-run
lsab plugins install /path/to/plugin.whl --sha256 EXPECTED_SHA256
lsab plugins install package-name==1.2.0
lsab plugins install https://github.com/OWNER/REPOSITORY --ref v1.2.0
lsab plugins install https://github.com/OWNER/REPOSITORY/releases/download/v1.2.0/PLUGIN.whl
lsab plugins install ./local-project --editable
```

Для индексных пакетов установщик предпочитает готовый wheel. Для Git он
сохраняет исходный ref и точный commit. Артефакт проверяется и кешируется
по SHA256. При наличии доверенного хеша передайте его через `--sha256`.
Хеш проверяет целостность артефакта. Доверие к автору и происхождению
пакета проверяет администратор. Установщик управляет дистрибутивами,
которые публикуют одну точку входа блока.

Сборка исходников, включая dry-run для каталога или Git, может выполнять
сборочный код. CLI запрашивает подтверждение до сборки и отдельно показывает
план перед переключением. Для скриптов используйте `--yes` только для
проверенных источников. `--dry-run` не создаёт новое окружение, не меняет
конфигурацию бота и не запускает службы.

`--editable` предназначен для локальной разработки. Рабочее дерево исходников
остаётся общей зависимостью окружений. Откат окружения восстанавливает набор
установленных пакетов; для восстановления правок в рабочем дереве используйте
его Git-историю. Откат конкретного пакета из кеша ставит сохранённый wheel.

## Обновление и удаление

```bash
lsab plugins outdated
lsab plugins update hello_system --dry-run
lsab plugins update hello_system --version 0.2.0
lsab plugins update hello_system --source /path/to/new-release.whl
lsab plugins update --all
lsab plugins remove hello_system
lsab plugins remove hello_system --purge
```

Индексные пакеты обновляются до стабильной версии, если явно не указан
`--pre`. Для Git установщик выбирает наиболее новую подходящую версионную
метку, а `--ref` позволяет выбрать определённую ревизию. Для локального
wheel и ссылки на конкретный релиз используйте новый `--source`.
`--all` выполняет обновления последовательно, каждое отдельной транзакцией.

План показывает версии, зависимости из отчёта pip и новые заявленные
разрешения. Версии уже установленных зависимостей фиксируются, включая
SDK и Telegram. Для изменения общего набора библиотек требуется отдельное
обновление основного окружения. Перед переключением выполняются `pip check`,
проверка манифестов и диагностика включённых блоков без Telegram polling.

Удаление отключает блок и удаляет его дистрибутив. Настройки, данные,
общие зависимости и история сохраняются. `--purge` создаёт резервную копию
и очищает активные настройки и данные выбранного блока.

При установке готового wheel с операциями брокера терминал предлагает выбрать
права для выдачи. Отдельную выдачу через `lsab-broker-admin` подтверждает
системный администратор. Плагин по-прежнему нужно включить после установки.
`--yes` и неинтерактивный запуск сами по себе прав не выдают. Если выдача
отклонена или не удалась, установленный блок остаётся выключенным, а результат
установки показывает состояние `broker_approval`.

При обновлении управляемого привилегированного пакета его старые права
отзываются после проверки нового окружения, до завершения транзакции.
Новая версия остаётся выключенной,
пока её не включит администратор. При удалении `lsab plugins remove` вызывает
системный инструмент для отзыва прав до завершения транзакции. Если отзыв
не удался, установщик восстанавливает предыдущее окружение. При прерывании
на шаге отзыва команда `lsab plugins environment recover` завершает отзыв.
Откат и повторная установка отозванные права не восстанавливают.
См. [описание операций в манифесте](external-plugins.md#операции-брокера).

## Рабочее окружение и восстановление

Перезапустите нативный установщик при переходе со старого systemd unit,
чтобы служба использовала `packaging/run-native.sh`. Для ручного запуска
используйте тот же скрипт. Он открывает выбранное окружение по каноническому
пути и блокирует второй ручной запуск из рабочей копии.

Менеджер создаёт venv в окончательном каталоге `runtime/environments`, копирует
пакеты из активного окружения и применяет изменения только к кандидату.
Символическая ссылка `runtime/current` заменяется атомарно. В
`runtime/previous` сохраняется предыдущее рабочее окружение.
Установленные дистрибутивы, происхождение и хеши хранятся в метаданных
окружения. Конфигурация блоков и пользовательские данные находятся отдельно.

Работающая пользовательская служба systemd сначала останавливается.
Установщик ждёт отчёт о готовности нового PID из нужного окружения.
При отказе возвращаются предыдущая ссылка и конфигурация, а для операции,
снимавшей данные, ещё и резервная копия данных. Служба запускается снова из
предыдущего окружения. Перед переключением примените или откатите другие
накопленные изменения `blocks.toml`. В ручном режиме сначала завершите бота.

```bash
lsab plugins history
lsab plugins environment info
lsab plugins environment check
lsab plugins environment recover
lsab plugins rollback
lsab plugins rollback hello_system
lsab plugins rollback --config-only
lsab plugins cache info
lsab plugins cache clean
lsab plugins installer
```

`environment recover` завершает восстановление после прерванного
переключения. Укажите тот же способ запуска и путь конфигурации.
Откат одного плагина использует предыдущий артефакт из кеша и повторно
проверяет зависимости. Пакетные команды берут файловую блокировку.
Очистка кеша сохраняет колёса активных поколений и последних транзакций.

Для изменения `[data].schema_version` в манифесте укажите
`--allow-migration` при обновлении. Установщик делает резервную копию
активных файлов до запуска. Миграцию выполняет сам плагин. При явном
откате между несовместимыми схемами восстановите данные по инструкции
плагина. Резервные копии лежат в `runtime/transactions/<id>/backup`.

Проверка свободного места учитывает размер копии окружения. По умолчанию
сохраняются текущая и предыдущая версии. На этапе обновления нужно место
ещё для одного кандидата и временных файлов сборки. Кеш учитывается
отдельно.

## Docker

Сформируйте комплект из управляемых артефактов в нативном окружении.

```bash
lsab plugins environment export ./docker-plugins
```

Комплект содержит wheel, их хеши, зафиксированные версии и `plugins.lock`.
Включите каталог в сборку производного образа и устанавливайте зависимости
внутри сборки. Пример слоя для производного Dockerfile.

```dockerfile
FROM lsab-base
USER root
COPY docker-plugins/ /opt/lsab-plugins/
RUN cd /opt/lsab-plugins && (test ! -s wheels.sha256 || sha256sum -c wheels.sha256) && \
    python -m pip install --no-cache-dir -c constraints.txt -r requirements.txt && \
    python -m pip check
USER botuser
```

Используйте базовый образ с подходящими версиями ядра, Python и SDK. Для
возврата используйте предыдущий образ. Комплект включает пакеты, которыми
управляет установщик. Конфигурация и данные по-прежнему находятся в общем
каталоге Compose.
